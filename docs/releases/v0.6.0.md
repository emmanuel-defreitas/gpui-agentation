# 0.6.0 release correction

The maintainer intended **0.6.0**, not 6.0.0, for the annotation tools release.
On 2026-10-25, crates.io version 6.0.0 was yanked and the GitHub release and
`v6.0.0` tag were deleted. Yanking preserves existing lockfiles and downloads.
The [original stack notes](v6.0.0.md) remain as a historical record.

## Version policy and scope

The reviewed `.github/release-version.json` declares `0.5.1 → 0.6.0`.
Breaking API changes during 0.x development advance the minor version; after
1.0.0, they advance the major version. Metadata consistency, the minimum bump,
and reviewed merge-commit tagging remain mandatory. The normal preparation
command still rejects downgrades. This authorized correction uses the existing
version synchronization helper once to replace the withdrawn package number.

Cargo, its lockfile, MCP metadata, current documentation, the setup skill and
the website use 0.6.0. Settings, CLI and MCP versions derive from Cargo.
Annotation behavior and dependency pins are unchanged by this correction.

## Release path and verification

1. Merge the correction PR into `dev` after CI passes.
2. Promote `dev → next`, validate preview CI, then merge `next → main`.
3. Let the existing release workflow tag the reviewed merge commit `v0.6.0`.
4. Run the existing publisher on `main` with `version=0.6.0` and `publish=true`.
5. Verify the crates.io version, Cargo index checksum and archive commit.

Local checks: `make version-check version-test release-version-check`, Rust
formatting, workspace Clippy/tests, and release-build compilation. GitHub CI
repeats the required platform and publication checks before each merge/publish.
