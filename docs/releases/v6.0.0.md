## Behavior and integration

Turn annotation mode on to display and reserve I/B/A/P/C/T tool shortcuts.
Ctrl/Cmd+S saves the draft; Ctrl/Cmd+Z and Ctrl/Cmd+Shift+Z undo and redo.
Delete/Backspace removes the selected note outside its text editor. Text fields
retain ordinary character entry, deletion and text undo behavior.

Textboxes use plain text, one font style and size, and display on the canvas
after saving without opening a comment. Click to edit them. Comment panels
inherit their annotation's selected color. Drag numbered pins independently of
their drawings; moves and deletions can be undone. Undo refuses to overwrite a
note that changed concurrently through MCP or another window.

Include `gpui_agentation::debug_menu()` after the host's application menu in
its existing `cx.set_menus(...)` list. `Agentation::root` forwards commands to
the owning entity. Direct `AnnotationOverlay` hosts forward `AnnotationCommand`
from their root. The demo and consumer show this integration. The Debug menu
exposes tool, color, history, comments, MCP, settings and toolbar commands.
None hides the embedded toolbar; the host menu remains the command surface.

Toolbar placement persists in the notes store, keyed by application name.
Windows mounted against the same canonical path share the store and preferences;
symlinked paths and not-yet-created files resolve to the same identity. Banner
controls use theme colors on a transparent background; wide windows expose the
palette horizontally. MCP can be toggled from the toolbar with its official mark.

tests additionally cover host-shortcut precedence, None restoration through
menu-command dispatch, persistence, and concurrent-edit rejection. Full manual
menu-bar and multiple-window interaction coverage remains a review task.

## Explicit version policy

The requested version is explicitly **6.0.0**, not 0.6.0. The committed
`.github/release-version.json` declares the maintainer-approved `0.5.1 → 6.0.0`
jump and its reason. The existing `release_version.py` reads the declaration
from the reviewed Git revision, validates the latest reachable stable baseline
and minimum conventional bump, and still requires synchronized metadata.
After `v6.0.0` is tagged, ordinary version calculation resumes. Emoji-prefixed
commit subjects are supported; PR titles keep plain conventional prefixes.

`make release-version-check` now accepts 6.0.0 through the existing production
release workflow. Opening these PRs does not publish or merge the release.
See `.github/BRANCH-AND-RELEASE-POLICY.md` for validation and merge requirements.
